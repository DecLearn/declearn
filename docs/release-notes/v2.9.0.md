# declearn v2.9.0

Released: 26/08/2026

## Summary of changes

This release is mainly focused on performance: with the migration to **binary serialization**, the new **benchmark suite**, and **performance patches**. It also introduced a **new usage example** involving *time series*, and minor features, fixes and refactoring.

## Release Highlights

### MessagePack Serialization
Declearn serialization have been migrated from JSON (textual format) to **MessagePack** (binary format), especially for Declearn object network transfer (between server and clients).

Note that JSON serialization utilities have been kept to allow data dumping with human-readable format.

The migration to MessagePack format allows to be more memory-efficient and reduces the size of exchanged messages and file checkpoints (especially for model weights, that are **2x smaller** in binary format than before in hexadecimal textual format).

The serialization system have also been harmonized across Declearn, to make its maintenance easier for developers. For technical details about this backend update, see [the concerned merge request](https://gitlab.inria.fr/magnet/declearn/declearn/-/merge_requests/82).

### Add Benchmark suite
A benchmarking suite has been added in the `benchmarks` directory at project root. This side module contains :

- An [ASV](https://github.com/airspeed-velocity/asv)\-driven benchmark suite for federated learning using Declearn.
- Scripts to perform profiling on Declearn code with:
    - [py-spy](https://github.com/benfred/py-spy) for CPU/time profiling
    - [memray](https://github.com/bloomberg/memray) for memory profiling

These new tools allow:
- Per-release performance regression check (time & memory), comparing against the previous release tag's artifacts, and warning on a >1.5x regression.
- On-demand investigation with manual trigger of `asv` benchmarking, and `py-spy` / `memray` manual profiling.

The benchmark suite is made of Python modules, classes and functions matching `asv` requirements to run some parametrized FL experiments with Declearn (e.g. with distinct Deep Learning frameworks, regularizers, or number of clients).

A detailed developer guide on benchmarking and profiling has been added in `docs/dev-guide/benchmarks.md`.

### New example: time series
A new example of FL experiment with Declearn has been added, using time-series data. Specifically surface electromyography via N. Nasri & al, 2019 ([_EMGs datasets: Two datasets with EMGs signals of people making gestures_](https://www.rovit.ua.es/dataset/emgs/)).

This new example comes with utilities to work with these type of data, added to the library in `declearn.dataset.examples._time_series_emg`

See `examples/time-series/readme.md` for further details.

Note: all DecLearn examples have been harmonized (common CLI arguments, documentation, factorization of SSL-certificate-generation in one common script).

## Other changes

### Features
- New utility function for logging: `setup_root_logger` to easily configure loggers prefixed by "declearn" (all Declearn loggers should). This addition especially allows to configure loggers that are outside the server / client scope (the latter already having their own `setup_[...]_loggers` utilities).

- New mechanism of **lazy serialization support**: it consists in registering a type as "known by declearn", along with its module. In order to know which module we need to manually import to trigger the actual serialization support.  
=> prevent from raising errors when a separated client process has not manually imported torch / tensorflow submodules and receive a serialized object that depends on them. This new mechanism allows to remove the unused (but previously mandatory) manual import of these module in `run_client.py` example scripts.

### Bug fixes
Patch the `heart-uci` Declearn usage example, that was broken due to a previous API changes.

### Performance improvements
This release fixes three performance bottlenecks identified thanks to the new Declearn profiling tools. Here are the three performance patches:

- Network message compression
    - Adds a `compression` parameter to the `NetworkClient` and `NetworkServer` APIs, to let the user choose if the message should be compressed over the wire by the selected protocol. This allows the user to choose between saving performance (compression off) or bandwidth (compression on). Message compression is now off by default.

- Batched mask generation in masking-based SecAgg
    - Add a method to generate one mask array per vector instead of one per element.

- Precomputing of round max steps for DP budget
    - Replaces the per-step DP budget check with a once-per-round precomputation of the maximum number of allowed training steps.

See [MR 83](https://gitlab.inria.fr/magnet/declearn/declearn/-/merge_requests/83) and [MR 86](https://gitlab.inria.fr/magnet/declearn/declearn/-/merge_requests/86) for further details.

### Developer-oriented changes
- Remove the `declearn.test_utils` module (that was not part of the stable API). Utilities that were previously part of this module have been moved to other places, to one of :
    
    - `declearn.utils`
    - `declearn.utils.examples` (new module)
    - `test.testing_utils` (`test` is now a Python module with the new `testing_utils` submodule)
    - specific test submodules, as close as possible to their local usage

- Add git commit / branch naming conventions, and additional docstring style recommendations.
    
- Increase code coverage of the `client_sampler` module.
    

## API breaking changes

### Serialization
This release introduces breaking changes due to the migration and harmonization of the serialization system.

- Renaming :
    - `utils.json_load` / `utils.json_dump` -> moved to `utils/serialize/`.
    - `utils.serialize_numpy` -> renamed `utils.pack_numpy`.
    - `utils.deserialize_numpy` -> renamed `utils.unpack_numpy`.
- Removal :
    - remove `utils.json_pack`, `utils.json_unpack`.  
        -> to replace them, use directly the instance methods to get a JSON-serializable dictionary (ex: `to_dict` / `from_dict` for `Aggregate` subclasses).
    - remove `utils.add_json_support`.  
        -> JSON support can now be added using `utils.serialize.add_serialization_support(cls, "json", ...)`
    - remove legacy "object serialization" system (no longer used) :
        - `utils.ObjectConfig`,
        - `utils.deserialize_object`,
        - `utils.serialize_object`.
    - remove `communication.api.backend.actions.LegacyReject` and `LegacyMessageError` (no longer used).

### Client sampling
Some renaming have been performed in the `client_sampler` module for clarity purpose. It introduces quickly-fixable breaking changes, you just need to rename the symbols if you used them.

- `ClientSampler.sample` -> renamed `ClientSampler.run`
- `ClientSampler.cls_sample` -> renamed`ClientSampler.sample`
- `TrainTimeHistoryCriterion`'s `agg` attribute -> renamed `agg_func`

## Deprecation
The following functions in logging utilities (`declearn.utils`) have been renamed and are now deprecated, they will be removed in version 2.10:

- `config_logger` -> renamed `setup_logger`
- `config_server_loggers` -> renamed `setup_server_loggers`
- `config_client_loggers` -> renamed `setup_client_loggers`
